# Политика безопасности

[English version](SECURITY.md)

## Поддерживаемая версия

Исправления безопасности применяются к актуальному `main` и к отдельно объявленным поддерживаемым релизам.

`v1.0.0` — первый стабильный релиз.

## Сообщение об уязвимости

Не публикуйте в открытом issue учётные данные, exploit details, stream keys, приватные URL или адреса назначений.

Сообщайте владельцу репозитория по согласованному приватному каналу.

Укажите:

- версию или commit;
- компонент;
- шаги воспроизведения;
- влияние;
- факт утечки данных или credentials;
- возможное исправление.

## Конфиденциальные данные

Нельзя коммитить и публиковать:

- backend `.env`;
- JWT secrets;
- пароли PostgreSQL;
- deploy keys;
- SSH private keys;
- TLS private keys;
- приватные URL источников;
- RTMP stream keys;
- tokenized HLS URL;
- production dumps.

## Роли

- Viewer не получает `source_url` и `destination_rtmp_url`;
- Operator видит оба URL, управляет потоком и меняет source;
- Operator не меняет RTMP destination definitions;
- Administrator имеет полный доступ.

Граница безопасности — backend authorization. Скрытия кнопок недостаточно.

## HLS-preview

- HLS нельзя публиковать открытым Nginx alias;
- preview выдаётся через авторизованный API;
- токены короткоживущие;
- URL с токенами не пишутся в access log;
- HLS временный и не является архивом.

## Production

- открывать только необходимые порты;
- не публиковать PostgreSQL;
- использовать SSH keys;
- ограничивать Administrator;
- использовать HTTPS;
- сохранять Certbot TLS;
- делать backup до миграций и обновлений;
- обновлять компоненты в maintenance window;
- контролировать повторные auth/process ошибки.

## Реакция на инцидент

1. Остановить затронутые потоки при риске публикации.
2. Отключить или сбросить аккаунты.
3. Заменить JWT, DB, deploy или stream credentials.
4. Сохранить журналы и данные.
5. Восстановить известную рабочую версию.
6. Проверить права Viewer и Operator.
7. Зафиксировать причину и исправление.
