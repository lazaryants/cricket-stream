# Cricket Stream Platform 1.0.0

[English version](../en/RELEASE_NOTES_v1.0.0.md)

**Дата выпуска:** 2026-08-03  
**Тег релиза:** `v1.0.0`

## Обзор

Версия **1.0.0** — первый стабильный релиз Cricket Stream Platform.

Платформа предоставляет самостоятельную среду для получения live-источников, передачи их на RTMP-назначения, контроля видеотракта и управления несколькими трансляциями из одного веб-интерфейса.

Штатный видеотракт использует копирование видео и аудио. Это снижает нагрузку на CPU и сохраняет исходный закодированный поток, если источник и принимающая площадка совместимы.

## Главное в релизе

- Полностью английский и русский интерфейс
- Движки Streamlink и yt-dlp
- RTMP-передача и защищённый HLS-preview
- Dashboard и монитор с сетками 1/4/9/16
- Библиотеки источников и RTMP-назначений
- Онлайн-метрики, диагностика, сессии и журналы
- Роли Viewer, Operator и Administrator
- Проверка версий компонентов и наличия обновлений
- PostgreSQL и миграции Alembic
- Production-развёртывание через Nginx, HTTPS и systemd

## Рабочий сценарий

Администратор или оператор может:

1. Выбрать или ввести источник
2. Выбрать движок источника
3. Выбрать или ввести RTMP-назначение
4. Запустить поток
5. Проверить preview, метрики и диагностику
6. Контролировать трансляцию на Dashboard или Monitor
7. Остановить поток и изучить завершённую сессию

Желаемое активное состояние позволяет восстановить настроенные трансляции после перезапуска backend.

## Видеотракт

```mermaid
flowchart LR
    A[YouTube / Twitch / Kick / Vimeo / прямой источник]
    --> B{Streamlink или yt-dlp}
    --> C[FFmpeg]
    --> D[RTMP-назначение]

    C --> E[Защищённый HLS-preview]
    E --> F[Авторизованный браузер]
```

FFmpeg получает источник один раз и создаёт оба выхода без перекодирования в стандартной конфигурации.

## Роли

### Viewer

- Видит разрешённые статусы, метрики, диагностику, сессии и preview
- Не может запускать, останавливать или редактировать трансляции
- Не получает URL источников и назначений

### Operator

- Видит URL источника и назначения
- Запускает и останавливает трансляции
- Изменяет настройки источника
- Не может изменять определения RTMP-назначений

### Administrator

- Имеет все права Operator
- Управляет RTMP-назначениями
- Управляет пользователями и паролями
- Имеет доступ к административным страницам

## Обновление

Production-базу необходимо сохранить.

Перед обновлением:

```bash
cd /opt/cricket-stream
git status

cp backend/.env ~/cricket-backend.env.backup

sudo -u postgres pg_dump \
  --format=custom \
  cricket_stream \
  > ~/cricket-stream-db.backup.dump

sudo cp -a \
  /etc/nginx/sites-available/cricket-stream \
  /etc/nginx/sites-available/cricket-stream.backup
```

Обновление кода и зависимостей:

```bash
cd /opt/cricket-stream
git pull --ff-only

cd backend
uv sync --locked
.venv/bin/alembic upgrade head
.venv/bin/alembic check

cd ../frontend
npm ci
npm run build

sudo systemctl restart cricket-backend
sudo systemctl status cricket-backend --no-pager -l
```

Не заменяйте production-файл `.env` примером `.env.example` и не перезаписывайте управляемую Certbot конфигурацию Nginx шаблоном из репозитория при обычном обновлении приложения.

## Обновления компонентов

Страница Components показывает установленные версии и, для поддерживаемых компонентов, доступные версии.

Наличие обновления носит информационный характер. Streamlink, yt-dlp, FFmpeg, Python или Node.js следует обновлять только в плановое окно с последующей проверкой реальных источников и назначений.

## Известные ограничения

Версия 1.0.0 пока не содержит:

- Запуск по расписанию
- Автоматический старт после появления live-источника
- Полное управление несколькими узлами
- Историческую аналитику и отчёты по трафику
- Запись и архивное хранение
- Отправку уведомлений
- Поддерживаемый публичный API интеграции
